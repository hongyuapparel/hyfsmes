# 财务收支看板启用与验收

本轮是人民币收支管理，尚不是部门利润核算。公共分摊比例、库存成本、待收待付没有用估计数替代。

历史账表中的退款、工资扣款可以作为负数支出冲减，必须在备注说明原因。支出汇总是包含冲减的净额。工资若已按实发净额登记，不得再录一次扣款；有工资明细拆分时，也不能再重复录一笔工资合计。

## 发布顺序

1. 备份目标库的财务流水和资金账户表，确认库名。先执行一次 `backend/scripts/finance-controls-20260912.sql`，再部署同版本后端和前端。SQL 不填充期初或历史流水性质；不可重复盲目执行 ALTER TABLE。
2. 后端现有权限种子会添加财务操作权限；管理员继承，其他角色在“角色与权限”分别配置收入/支出的登记、修改、删除与恢复，以及资金核对、转账登记和转账作废。页面只读权限不再允许写账。
   若启用现有 `finance` 专职财务角色的全部九项财务操作，可执行 `backend/scripts/finance-role-permissions-20260913.sql`；先核对目标角色，执行后应返回九项权限。该 SQL 不授予其他角色，不将老板只读角色变成可写。当前仅在独立测试库配置并验收，线上尚未执行。
3. 不需要让销售或工厂再录一套账。财务继续一次登记实际收付款，选择账户、性质、受益部门；订单号不是必填。银行流水号可用于明确防重。

同账户的银行流水号在收入、支出（含负数冲减）、内部转账之间统一查重；新增、修改、恢复均检查，并发请求在账户锁内检查。不同账户可出现相同号码。未填写流水号仍需按原单据核对，不能依靠系统证明没有重复。

内部转账支持按账户名称、流水号、备注查询，按有效／已作废／全部状态筛选并分页；作废记录保留查询与操作留痕。

## 第一个核对期间

- 先确定纳入的公司资金账户，私账只包含公司部分。外币不得直接按人民币数字录入；本期先以可核实的人民币金额为口径。
- 选一个明确的期初日期，输入该日期开始之前的余额和来源。期初日期以前的流水仍可查，但不再次计入当前账面余额。
- 使用已有收支账及银行/平台流水完成所选期间核对，处理漏记、重复、失效部门、未归属和未分类；内部转账若原来两边分别记过，先核实原两笔，再替换为独立转账，不能三笔同时保留。
- 财务确认逐笔无遗漏、余额一致后，在“资金核对与内部转账”填写核对截止日期及银行期末余额。金额不符不能确认；核对后锁定对应日期以前的收付款和转账。
- 更正锁定流水时先填写原因撤销核对，修改完成后重新核对；不借用供应商改名等其他功能修改历史账务。
- 在上述数据真实完整前，老板只查看投入与回收，不以收支结余决定部门盈亏。之后再确认公共费用分摊规则和库存成本数据来源。

## 检查范围

- `node --test backend/test/finance-controls.local.test.js`：仅允许 localhost/127.0.0.1 数据库，使用独立测试账户、流水和只读角色，结束时清理自身生成的 ID。验证金额/日期、查重、版本冲突、账户余额、内部转账排除、对账锁定/撤销、软删除/恢复、留痕、权限、看板与明细合计。
  设置环境变量 `FINANCE_TEST_ROLE=finance` 可用现有财务角色的临时测试用户执行同一链路。新增覆盖跨收入／负数支出／转账查重、反向录入顺序、修改与恢复、并发竞争，以及 101 条转账的分页、作废筛选和无结果查询。
- `npm --prefix backend run build`、`npm --prefix frontend run build`：前后端类型及构建检查；前端包含字号和单选控件规范。
- 浏览器需实际验证：日期和性质切换、部门金额跳转、无结果、清空、分页；表单校验、保存、重新打开、修改、取消；批量删除、回收站与恢复；资金核对、差额提示、转账、操作记录。用隔离测试数据，不改实际账务。
- 常用窗口及 600×500 窗口检查大金额不拆字、表格末行、弹窗长内容及底部按钮可达。测试结论仅覆盖已验证场景，不代表所有数据、外币或生产环境都已验收。
